# SRAM Scout — STM32F407 外部 SRAM 内存侦察兵

一个把"外部 SRAM 能不能用"升级为"外部 SRAM 到底有多大、哪里坏、能跑多快"的自检工具。

基于正点原子 探索者 STM32F407 开发板（STM32F407ZGTx），在原有 SRAM 例程之上重建。

---

## 侦探什么

普通例程回答"这块内存通电了吗"——每 4 KB 写一个字节，256 个点，能读回不同的值就算通过。

本项目要回答的是：

- **容量**：FSMC 给了 64 MB 的地址窗口，实际能寻址的存储空间有多大？
- **边界**：超出真实容量的地址会发生什么——读回垃圾，还是**回卷到已用地址**？
- **可靠**：不只是"能读能写"，而是**哪些位是坏的、坏成什么样**？
- **性能**：读写带宽是多少？FSMC 时序参数的极限在哪里？

---

## 阶段 1 结论（已完成）

```
地址窗口       : 0x6800 0000 ~ 0x6BFF FFFF  (64 MB)
最小别名步长   : 0x0010 0000  (1 MB)
真实可用容量   : 1 MB
镜像因子       : 64        (64 MB ÷ 1 MB)
幽灵地址       : 0
判定           : 地址线仅 A0 ~ A18 已连接，A19 及以上悬空
```

**物理含义**：访问 `0x68100000` 时，MCU 发出的高位地址未被 SRAM 接收，芯片只看到 A18~A0 = 0，因此实际访问第 0 个半字。**1 MB 的物理芯片在 64 MB 的窗口中出现了 64 次。**

### 结论是怎么得出来的

| 实验 | 基准 | 步长 | 结果 |
|---|---|---|---|
| 一 | `0x68000000` | 1 MB | 63 点全 ALIAS |
| 二 | `0x68000000` | 512 KB | 31 ALIAS / 32 INDEP |
| 三 | `0x68080000` | 512 KB | 31 ALIAS / 32 INDEP（与实验二一致） |

三个关键方法：

1. **512 KB 对照组是必需的**。实验一的所有探测点都是 1 MB 的整数倍，因此"芯片 1 MB"与"芯片只有 1 个存储单元"两种假设会给出**完全相同**的输出。只有引入 512 KB 偏移的点才能把两者分开。

2. **每个结论都要有正向证据**。判定"独立单元"不能只看"读 A 仍是原值"——那也可能是 B 的写入压根没生效。必须**再读一次 B**，确认它真的写进去了。

3. **算术预测与硬件实测交叉验证**。`off % 1MB == 0` 是纯算术，`alias_probe_word()` 是纯硬件，两条独立路径在 **126/126** 个探测点上完全吻合，零例外。

完整报告见 [`Doc/阶段1报告_外部SRAM容量与别名周期探测.md`](Doc/阶段1报告_外部SRAM容量与别名周期探测.md)。

## 硬件配置

### FSMC 分区

| 片选 | 地址窗口 | 本板用途 |
|---|---|---|
| NE3 | `0x6800 0000` ~ `0x6BFF FFFF` | **外部 SRAM** |
| NE4 | `0x6C00 0000` ~ `0x6FFF FFFF` | LCD 控制器 |

### NE3 引脚

| 信号 | 引脚 |
|---|---|
| A0 ~ A5 | PF0 ~ PF5 |
| A6 ~ A9 | PF12 ~ PF15 |
| A10 ~ A15 | PG0 ~ PG5 |
| A16 ~ A18 | PD11 ~ PD13 |
| NE3（片选） | PG10 |
| D0 ~ D15 | PD0/1/8/9/10/14/15、PE7 ~ PE15（**与 LCD 共用**） |
| NOE / NWE | PD4 / PD5（**与 LCD 共用**） |

> **A19 及以上未连接**：PE2 / PE3 / PE4 在这块板子上分别是 KEY2 / KEY1 / KEY0，而它们正是 FSMC 的 A23 / A19 / A20。这就是容量止步于 1 MB 的硬件原因——已被实测证实。

## 编译与运行

1. 用 **Keil MDK** 打开 `Projects/MDK-ARM/atk_f407.uvprojx`
2. 编译并烧录
3. 串口连接 USART1：**115200-8-N-1**
4. 上电后应看到门控输出 `[GATE] PASS @0x68000000`
5. 按下 **KEY0** 触发扫描（可重复触发）

### LCD 显示

```
SRAM SCOUT  v0.1
────────────────────────
Window : 0x68000000
Hyp.ALIAS : 1MB
Hyp.CAPAC.: 1MB
────────────────────────
Scan1: 31A 32I 0G p63/63
Scan2: 31A 32I 0G p63/63
CONFIRMED
────────────────────────
KEY0: re-scan
```

> `Hyp.` 两行是**硬编码的假设**，只有在扫描判出 `CONFIRMED` 后才成为结论。
> `p63/63` 是"算术预测命中数 / 总探测点数"。

## 核心接口

```c
/* 写通道门控自检：测量前必须通过，否则中止 */
Gate_Status SRAM_WriteChannel_SelfTest(void);

/* 参数化别名扫描 */
Scan_Status SRAM_AliasScan_Param(uint32_t base, uint32_t step,
                                 uint32_t k_max, ScanStats *out);
```

`ScanStats` 同时携带测量结果与实验条件（base / step / k_max），便于报告引用。
`pred_ok` / `pred_bad` 记录算术预测与硬件实测的吻合情况，**正常时 `pred_bad` 必须为 0**。

## 开发中遇到的坑

记录几个隐蔽且症状具有欺骗性的问题：

| 问题 | 症状 | 根因 |
|---|---|---|
| `WriteOperation` 未赋值 | **写通道完全失效**：读有值、写无效 | `USE_FULL_ASSERT` 未开启，参数检查全部失效；`FSMC_WRITE_OPERATION_ENABLE` 是唯一非零枚举值，结构体零初始化时 WREN = 0 |
| 时序结构体未清零 | 时序寄存器写入**栈垃圾**，行为随机 | 局部结构体只赋了部分字段 |
| LCD 行坐标重叠 | 分隔线压住相邻文字 | 分隔线用 `'-'` 字符串绘制（占满 16 px 文字行），而间隔仅 `+4` |
| Verdict 判据过弱 | 写通道部分失效时仍报"一致" | 仅检查两次扫描结果相等，未检查与算术预测的吻合 |

> 第一条尤其危险：它的症状（所有地址看似互相别名）**恰好长得像被考察的假设之一**。这正是必须在测量前执行门控自检的原因——把"工具坏了"和"发现是它"分开。
