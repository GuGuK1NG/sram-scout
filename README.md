# SRAM Scout — STM32F407 外部 SRAM 内存侦察兵

一个把"外部 SRAM 能不能用"升级为"外部 SRAM 到底有多大、哪里坏、能跑多快"的自检工具。

基于正点原子 探索者 STM32F407 开发板（STM32F407ZGTx），在原有 SRAM 例程之上重建。

---

## 侦探什么

普通例程回答"这块内存通电了吗"——每 4 KB 写一个字节，256 个点，能读回不同的值就算通过。

本项目要回答的是：

- **容量**：FSMC 给了 64 MB 的地址窗口，实际能寻址的存储空间有多大？
- **边界**：超出真实容量的地址会发生什么——读回垃圾，还是**回卷到已用地址**？
- **可靠**：不只是"能读能写"，而是**哪些位是坏的、坏成什么样**？
- **性能**：读写带宽是多少？FSMC 时序参数的极限在哪里？

## 阶段 1 结论：容量与别名周期

```
地址窗口       : 0x6800 0000 ~ 0x6BFF FFFF  (64 MB)
最小别名步长   : 0x0010 0000  (1 MB)
真实可用容量   : 1 MB
镜像因子       : 64        (64 MB ÷ 1 MB)
幽灵地址       : 0
判定           : 地址线仅 A0 ~ A18 已连接，A19 及以上悬空
```

**物理含义**：访问 `0x68100000` 时，MCU 发出的高位地址未被 SRAM 接收，芯片只看到 A18~A0 = 0，因此实际访问第 0 个半字。**1 MB 的物理芯片在 64 MB 的窗口中出现了 64 次。**

### 结论是怎么得出来的

| 实验 | 基准 | 步长 | 结果 |
|---|---|---|---|
| 一 | `0x68000000` | 1 MB | 63 点全 ALIAS |
| 二 | `0x68000000` | 512 KB | 31 ALIAS / 32 INDEP |
| 三 | `0x68080000` | 512 KB | 31 ALIAS / 32 INDEP（与实验二一致） |

三个关键方法：

1. **512 KB 对照组是必需的**。实验一的所有探测点都是 1 MB 的整数倍，因此"芯片 1 MB"与"芯片只有 1 个存储单元"两种假设会给出**完全相同**的输出。只有引入 512 KB 偏移的点才能把两者分开。

2. **每个结论都要有正向证据**。判定"独立单元"不能只看"读 A 仍是原值"——那也可能是 B 的写入压根没生效。必须**再读一次 B**，确认它真的写进去了。

3. **算术预测与硬件实测交叉验证**。`off % 1MB == 0` 是纯算术，`alias_probe_word()` 是纯硬件，两条独立路径在 **126/126** 个探测点上完全吻合，零例外。

完整报告见 [`Doc/阶段1报告_外部SRAM容量与别名周期探测.md`](Doc/阶段1报告_外部SRAM容量与别名周期探测.md)。

## 阶段 2 结论：数据总线健康

**测出的结果：6 个测试地址 × 16 位 = 96 个格子全部正常。**

但这句"全部正常"之所以可信，靠的不是"跑完没报错"，而是下面三件事：

### 1. 双向跳变覆盖（Walking-1 + Walking-0）

每个存储位需要经历**两个跳变方向**，两个方向的物理路径不同（CMOS 拉高靠 PMOS、拉低靠 NMOS）：

| | 被测位 | 其余 15 位 | 覆盖 |
|---|---|---|---|
| **Walking-1** | 从 0 升到 1 | 恒 0 | 上升跳变、上升耦合 |
| **Walking-0** | 从 1 降到 0 | 恒 1 | 下降跳变、下降耦合 |

**两者不是"做两遍"，而是两种不同的实验条件。** 某些故障只在其中一个方向暴露。

> 注：只要比对完整的 16 位读回值，**两种极性**的 stuck-at 故障在**任一方向**都能查出。两个方向的主要价值在于**覆盖不同的跳变/耦合方向**，以及拆解多重故障互相掩盖的情况。

### 2. 故障分诊：是"线"还是"格子"

同样的"某位读不对"，成因完全不同：

| 现象 | 判定 | 处理方式 |
|---|---|---|
| 某位在**所有**地址都异常 | **数据线故障** | 查 MCU 走线、焊接 |
| 某位**只在部分**地址异常 | **存储单元故障** | 芯片内部格子损坏 |

**只测一个地址，这两种情况分不开。** 因此扫描覆盖 6 个地址（跨越不同的物理存储区域），再由分诊逻辑自动判定。

### 3. 与阶段 1 的交叉复验

测试地址中 `A0`(0x68000000) 与 `A5`(0x68100000) 相差整整 1 MB。按阶段 1 的结论，**两者是同一个物理单元**，因此数据测试结果**必须逐位相同**。

实测：`16/16 bit identical` —— 跨阶段的独立复验通过。

### 4. 工具自检：证明"能报错"

一个永远报 OK 的测试和一个健康的芯片，**输出完全相同**。因此用**故障注入**验证了判定逻辑的**每一条分支**都能被触发：

| 模式 | 分支 | 语义 | 验证 |
|---|---|---|---|
| Walking-1 | `OK` | 该位升到 1，正确 | ✅ |
| Walking-1 | `S0` | 该位升不上去（stuck-at-0） | ✅ |
| Walking-1 | `BR` | 该位正确，异常在**别的位** | ✅ |
| Walking-0 | `OK` | 该位降到 0，正确 | ✅ |
| Walking-0 | `S1` | 该位降不下来（stuck-at-1） | ✅ |
| Walking-0 | `BR` | 该位正确，异常在**别的位** | ✅ |

**6 条路径全部被独立触发过** —— 没有死代码。

## 硬件配置

### FSMC 分区

| 片选 | 地址窗口 | 本板用途 |
|---|---|---|
| NE3 | `0x6800 0000` ~ `0x6BFF FFFF` | **外部 SRAM** |
| NE4 | `0x6C00 0000` ~ `0x6FFF FFFF` | LCD 控制器 |

**扫描时绝不能越过 `0x6C000000`** —— 那里是 LCD，写进去会打花屏幕。

### NE3 引脚

| 信号 | 引脚 |
|---|---|
| A0 ~ A5 | PF0 ~ PF5 |
| A6 ~ A9 | PF12 ~ PF15 |
| A10 ~ A15 | PG0 ~ PG5 |
| A16 ~ A18 | PD11 ~ PD13 |
| NE3（片选） | PG10 |
| D0 ~ D15 | PD0/1/8/9/10/14/15、PE7 ~ PE15（**与 LCD 共用**） |
| NOE / NWE | PD4 / PD5（**与 LCD 共用**） |

> **A19 及以上未连接**：PE2 / PE3 / PE4 在这块板子上分别是 KEY2 / KEY1 / KEY0，而它们正是 FSMC 的 A23 / A19 / A20。这就是容量止步于 1 MB 的硬件原因——已被实测证实。

## 核心接口

```c
/* ---- 阶段 1 ---- */

/* 写通道门控自检：测量前必须通过，否则中止 */
Gate_Status SRAM_WriteChannel_SelfTest(void);

/* 参数化别名扫描 */
Scan_Status SRAM_AliasScan_Param(uint32_t base, uint32_t step,
                                 uint32_t k_max, ScanStats *out);


/* ---- 阶段 2 ---- */

/* 逐位游走测量。
 * mode = 0 : Walking-1（单个 1 游走，第 i 位期望 1）
 * mode = 1 : Walking-0（单个 0 游走，第 i 位期望 0）
 * out[16]  : 各位状态；raw[16] : 原始读回值（供跨图案分析）
 * 返回通过位数 0~16 */
uint32_t sram_walk(uint32_t addr, BitStatus *out, uint16_t *raw,
                   uint8_t mode);

/* 六地址矩阵扫描（含门控、交叉验证、自动分诊） */
Scan_Status sram_run_bus_matrix(void);

/* 矩阵报告打印 */
void sram_run_bus_matrix_print(const BusReport *rep, uint8_t mode);
```

### 关键数据结构

```c
typedef enum {              /* AC6 下枚举自动压缩为 1 字节 */
    BIT_OK     = 0,
    BIT_STUCK0 = 1,         /* 该位恒 0 */
    BIT_STUCK1 = 2,         /* 该位恒 1 */
    BIT_BRIDGE = 3,         /* 本位正常，异常在别的位 */
} BitStatus;

typedef struct {
    uint32_t  addr;         /* 测试地址 */
    uint32_t  pass;         /* 通过位数 0..16 */
    BitStatus st[16];       /* 各位状态，st[0]=D0 */
    uint16_t  raw[16];      /* 原始读回值，供交叉比对 */
} BusAddrResult;

typedef struct {
    BusAddrResult a[BUS_ADDR_CNT];   /* BUS_ADDR_CNT = 6 */
    uint32_t      cnt;               /* 实际测量个数（被跳过的地址不占槽位） */
} BusReport;
```

> **`raw[]` 必须保留** —— 区分"stuck-at-1"与"位间短路"需要跨图案比对原始读回值，单凭状态标记做不到。

## 故障注入：验证工具本身

**一个永远报 OK 的测试，和一个健康的芯片，输出完全相同。** 所以在 `sram_walk()` 里内置了故障注入，用来验证判定逻辑的每条分支。

```c
rd = *p;                    /* 读回真实值 */

/* ---- 故障注入（验证完请注释掉） ---- */
if(i == 0){ rd = 0x0000; }              /* 伪造 D0 恒 0 */
if (i == 5){ rd |= (1u << 5); }         /* 伪造 D5 降不下来 */

if (raw != 0) raw[i] = rd;  /* raw[] 保存的是【注入前】的真实值 */
```

**⚠️ 当前仓库状态：注入处于启用状态。** 正常测量前请先注释掉这两行。

**注入的两种写法和效果**：

| 写法 | 含义 | 适用 |
|---|---|---|
| `rd \|= mask` | 把 mask 的位**置 1** | 触发 `STUCK1` / `BR` |
| `rd &= ~mask` | 把 mask 的位**清 0** | 触发 `STUCK0` |
| `rd &= mask` | **只保留** mask，其余全清 | 破坏性强，慎用 |

> **注意**：注入用 `i`（位号）作条件时**与地址无关**，6 列结果相同 → 只能触发"数据线故障"。若要触发"存储单元故障"，条件里要加上地址：
> ```c
> if (addr == 0x68000100 && i == 5) { rd |= (1u << 2); }
> ```

## 已知局限

如实记录当前证据链中可被质疑的部分。

### 阶段 1

| 未做的实验 | 预期结果 | 能排除的质疑 |
|---|---|---|
| 翻转测试：`base = 0x68040000` | 预测 **0 个 ALIAS** | 证明工具**能报出"没有别名"** |
| 签名无关性：更换签名 | 结论不变 | 排除"总线残留碰巧撞上签名" |
| 主动证伪：PD13（A18）驱动为低 | 预测步长变为 **512 KB** | 证明工具真的在读引脚，而非回显常量 |

### 阶段 2

| 局限 | 说明 |
|---|---|
| **`SCAN_OK` 语义模糊** | 它表示"扫描操作完成"，**不表示"数据线健康"**。因此 LCD 上 `Matrix: 6 addr OK` 在注入故障时仍会显示——健康结论只在串口输出里。 |
| **未测字节使能** | 8 位访问走 `NBL0/NBL1` 掩码，目前只用半字访问（刻意避开），该故障类型待阶段 2.4 覆盖。 |
| **未测温度/电压边界** | 所有测试在常温常压下完成。 |

## 开发中遇到的坑

按"症状的欺骗性"排序。**前几条尤其危险——它们的症状与被测对象本身的故障高度相似。**

| 问题 | 症状 | 根因 |
|---|---|---|
| **`WriteOperation` 未赋值** | **写通道完全失效**：读有值、写无效 | `USE_FULL_ASSERT` 未开启，参数检查全部失效；`FSMC_WRITE_OPERATION_ENABLE` 是唯一非零枚举值，结构体零初始化时 WREN = 0。**症状看起来像"所有地址互为别名"** |
| **栈溢出** | `??` 出现在数组**末尾**、**格式字符串被改写**、程序卡死 | 栈只有 1 KB，两个 `BusReport`（各 340 B）+ 调用开销超过上限。**"常量被改"是内存被非法覆写的铁证** |
| **`(rd & pat)` 误当成 `(rd & bit)`** | Walking-0 下第二个判定分支**永远进不去** | `pat` 在 Walking-0 下有 15 个 1，`& pat` 几乎永不为 0。掩码必须只对准被测位 |
| **`(rd & bit) == 1u`** | i ≥ 1 时分支**永远为假** | `rd & bit` 的结果是 `bit` 本身（1/2/4/…），只有 i=0 时才可能等于 1。应判 `!= 0` |
| **`for(b=0;b<16;++i)`** | **死循环**，程序卡住 | 递增了错误的变量。编译通过，无任何警告 |
| **`if(faults==0)` 写在循环内** | `all normal` **永远不打印** | 该检查必须在循环结束后。且前面的 `continue` 让正常位根本到不了这行 |
| **越界读到相邻变量** | 打印出 `0x00000006` 而非地址 | `rep.a[6]` 越界落在 `rep.cnt` 上，值恰好"看起来合理" |
| **时序结构体未清零** | 时序寄存器写入**栈垃圾**，行为随机 | 局部结构体只赋了部分字段 |
| **Verdict 判据过弱** | 写通道部分失效时仍报"一致" | 仅检查两次扫描结果相等，未检查与算术预测的吻合 |

### 三条贯穿始终的方法论

1. **测量前先门控自检** —— 先证明工具是活的，再测量。把"工具坏了"和"发现是它"分开。

2. **每个结论都要有正向证据** —— 不能靠推理。"A 仍是原值"不等于"B 写成功了"，必须再读一次 B。

3. **阴性结果不算结论** —— "全部正常"必须配合"能报出异常"的证明。工具若永远只输出一种结果，它和正确的工具输出一样。

## 术语

| 术语 | 含义 |
|---|---|
| **别名 / 镜像** | 多个不同地址映射到同一物理存储单元 |
| **别名步长** | 最小的非零别名偏移量，等于真实容量 |
| **幽灵地址** | 未连接任何存储单元的地址，读回值未定义 |
| **交叉写入** | 在两个地址分别写入不同签名，通过观察互相干扰判定是否同单元 |
| **门控自检** | 测量前验证写通道存活的检查 |
| **Walking-1 / Walking-0** | 单个 1 / 单个 0 在 16 位数据线上依次游走 |
| **Stuck-at** | 某位恒为 0 或恒为 1 的硬件故障 |
| **耦合故障** | 一个单元的翻转把相邻单元一起带翻 |
| **数据线故障 vs 存储单元故障** | 前者所有地址都受影响；后者只影响特定格子 |
