数据结构（`sram.h`）：

```c
typedef enum {
    BIT_OK     = 0,
    BIT_STUCK0 = 1,   /* 该位恒 0 */
    BIT_STUCK1 = 2,   /* 该位恒 1 */
    BIT_BRIDGE = 3,   /* 疑似与其它位短路（尚未实现判定） */
} BitStatus;
```

**已验证**：通过故障注入，确认 `S0` 和 `S1?` 两个判定分支都能正确报错，
且"额外为 1 的位"分析能精确指出是哪一位。

### 2.2 待做（下一步）

**前置改动**：把 `sram_walk1` 的故障注入**参数化**（当前是注释掉的硬编码）

```c
/* inj_mode: 0=不注入  1=强制为0(测S0分支)  2=强制为1(测S1分支)
 * inj_mask: 要注入的位 */
uint32_t sram_walk1(uint32_t addr, BitStatus *out, uint16_t *raw,
                    uint8_t inj_mode, uint16_t inj_mask);
```

**主体**：六地址矩阵扫描

| 编号 | 地址 | 相对基准 | 用意 |
|---|---|---|---|
| A0 | `0x68000000` | 0 | 基准 |
| A1 | `0x68000002` | +2 | 相邻半字 |
| A2 | `0x68000100` | +256 | 同页稍远 |
| A3 | `0x68080000` | +512 KB | 不同物理单元 |
| A4 | `0x680C0000` | +768 KB | 不同物理单元 |
| A5 | `0x68100000` | +1 MB | **预测与 A0 逐位相同**（阶段 1 别名结论） |

建议数据结构：

```c
#define BUS_ADDR_CNT  6

typedef struct {
    uint32_t  addr;
    uint32_t  pass;          /* 通过位数 0..16 */
    BitStatus st[16];        /* 各位状态, [0]=D0 */
    uint16_t  raw[16];       /* 原始读回值, 供桥接分析 */
} BusAddrResult;

typedef struct {
    BusAddrResult a[BUS_ADDR_CNT];
    uint32_t      cnt;
} BusReport;
```

**输出**：16 行 × 6 列矩阵（列头用 `A0~A5` 短名 + 图例，否则表格太宽）

**自动分诊**（2.2 的核心价值）：

```c
for (每一位 b) {
    bad = 0;
    for (每个地址 a) if (a.st[b] != BIT_OK) bad++;

    if (bad == 0)        → 正常
    else if (bad == cnt) → 【数据线故障】所有地址都坏 → 查走线/焊接
    else                 → 【存储单元故障】只有部分地址坏 → 该格子损坏
}
```

**阶段 1 交叉验证**：A5 与 A0 的 16 位判定结果必须**逐位相同**。
若不同，说明阶段 1 的别名结论有问题。

**注意**：2.2 做完后，**要用故障注入再自检一遍**——矩阵打印和分诊
逻辑本身也需要被验证，不能只看"全过"就信。

## 四、关键设计决策（为什么这么做）

| 决策 | 理由 |
|---|---|
| 用**半字**（`uint16_t`）访问，不用字节 | 这颗芯片物理访问单位是半字；字节访问走 `NBL0/NBL1` 掩码，是 2.4 专门要测的变量，先避开 |
| 测试地址必须是**偶地址** | 半字对齐要求 |
| 地址范围防护写在扫描函数**内部** | 工具应自己挡住危险参数（越过 `0x6C000000` 会打到 LCD） |
| 保留 `raw[]` 原始读回值 | 区分 stuck-at-1 与桥接**必须**跨图案比对原始数据 |
| `S1?` 带问号 | 单个图案无法区分 stuck-at-1 和桥接，标记"待确认" |
| 列头用 `A0~A5` 短名 | 6 个完整地址会让表格宽到无法阅读 |
