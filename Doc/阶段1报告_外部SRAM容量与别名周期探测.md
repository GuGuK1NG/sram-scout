# 阶段 1 报告：外部 SRAM 容量与别名周期探测

**项目**：SRAM 内存侦察兵（SRAM Scout）
**平台**：正点原子 探索者 STM32F407（STM32F407ZGTx）
**日期**：2026-09-20
**版本**：v0.1

---

## 摘要

本阶段的目标不是"确认外部 SRAM 能用"，而是**用测量确定它的真实容量与地址译码行为**。经三组独立实验测量，得到结论：

> **最小别名步长 = 0x00100000（1 MB）；真实可用容量 = 1 MB；地址线仅 A0~A18 已连接，A19 及以上悬空。**

该结论与由硬件配置（按键占用 PE3/PE4 引脚）推导出的理论预测**完全吻合**，并通过 126 个探测点的"算术预测 vs 硬件实测"交叉验证，零例外。

---

## 1. 目标

原始例程提供的测试是"每 4 KB 写 1 个字节，共 256 个点"，其作用是**证明这块内存通电了**，而非证明它有多大多可靠。本阶段要回答的是更本质的问题：

1. FSMC 分配给 NE3 的 64 MB 地址窗口中，**实际可寻址的存储空间有多大**？
2. 超出真实容量的地址会发生什么——读回垃圾、还是**回卷到已使用的地址**？
3. 能否用一个**可自证可靠**的方法把这个边界测出来？

第 3 点尤其重要：一个"永远报别名"的工具和一个真正的侦察兵，输出可能一样。本阶段的方法论重点就在于让工具的输出**可以被独立验证**。

## 2. 硬件配置

### 2.1 FSMC 分区

| 片选 | 地址窗口 | 大小 | 本板用途 |
|---|---|---|---|
| NE1 | `0x6000 0000` ~ `0x63FF FFFF` | 64 MB | 未使用 |
| NE2 | `0x6400 0000` ~ `0x67FF FFFF` | 64 MB | 未使用 |
| **NE3** | **`0x6800 0000` ~ `0x6BFF FFFF`** | **64 MB** | **外部 SRAM** |
| NE4 | `0x6C00 0000` ~ `0x6FFF FFFF` | 64 MB | LCD 控制器 |

FSMC 用 `HADDR[25:0]` 译码，四个片选窗口合计 256 MB。

### 2.2 NE3 引脚分配（本项目实现）

| 信号 | 引脚 | 说明 |
|---|---|---|
| A0 ~ A5 | PF0 ~ PF5 | 地址线 |
| A6 ~ A9 | PF12 ~ PF15 | 地址线 |
| A10 ~ A15 | PG0 ~ PG5 | 地址线 |
| A16 ~ A18 | PD11 ~ PD13 | 地址线 |
| **NE3** | **PG10** | 片选（由 FSMC 硬件产生） |
| D0 ~ D15 | PD0/1/8/9/10/14/15、PE7~PE15 | 数据线，**与 LCD 共用** |
| NOE / NWE | PD4 / PD5 | 读/写选通，**与 LCD 共用** |

**共用的含义**：SRAM 与 LCD 挂在同一组数据线和读写选通上，仅片选不同（NE3 vs NE4）。因此 `HAL_SRAM_MspInit()` 只需一份，负责配置 D0~D15 与 NOE/NWE；NE3 与地址线由本模块单独配置。

### 2.3 关键约束：A19 及以上不可用

`readme.txt` 给出的按键分配为 **KEY0-PE4、KEY1-PE3、KEY2-PE2**。查阅 STM32F407 复用功能表：

| 引脚 | FSMC 功能 | 板上用途 |
|---|---|---|
| PE2 | FSMC_A23 | KEY2 |
| PE3 | **FSMC_A19** | KEY1 |
| PE4 | **FSMC_A20** | KEY0 |

即 **A19、A20、A23 所在引脚全部被按键占用**。由此推导出的理论预测：

> 可用地址线最多到 **A18**（共 19 根）
> → 最大容量 = 2^19 个半字 = **1 MB**
> → 别名步长应为 **0x00100000**

**这一条预测是本阶段实验的设计依据，也是最终被测量证实的关键闭环。**

## 3. 方法论

### 3.1 核心思想：每个结论都必须有正向证据

朴素做法是"写一个值、读回来比对"。它有两个致命缺陷：

- **无法区分"别名"与"写入丢失"**。若目标地址根本没接到存储单元，写入会石沉大海，读回仍是旧值——朴素做法会把它误判为"独立单元"。
- **容易被总线残留欺骗**。悬空地址的读回值未定义，偶尔等于签名就会造成假阳性。

因此本项目采用 **交叉写入（cross-write）+ 双向扰动 + 证据链**：

```
单点判定 alias_probe_word(A, B):

  方向1（写 A 后写 B，读 A）:
    读 A == SIG2                        → B 的值出现在 A 的单元 → ALIAS
    读 A == SIG1 且 读 B == SIG2        → 各自保持原值，且 B 确已落地 → INDEP
    其它                                → B 的写入未落地 → GHOST

  方向2（写 B 后写 A，读 B）: 镜像同上

  两向结论必须一致；矛盾则判 GHOST（宁可不给结论，也不给不可信结论）
```

三个设计要点：

| 要点 | 理由 |
|---|---|
| **INDEP 必须二次读 B** | "A 仍为 SIG1" 只能说明 A 没变，**不能证明 B 写成功**。必须确认 `B == SIG2` 才算有证据 |
| **双向扰动** | 别名是**互相**的。只测"写 B 扰动 A"会漏掉单向故障造成的假 ALIAS |
| **`__DSB()` 内存屏障** | Cortex-M4 有写缓冲。写完立刻读，读可能抢在写落到总线之前，导致误判。这是必须的 |

### 3.2 测量前门控：先证明工具可靠

所有测量都建立在"写入真的生效"这一前提上。因此每次扫描前先执行 **写通道活体检测**：

```
写 BASE ← SIG_GATE，__DSB()，读回
写 BASE ← SIG1，    __DSB()，读回
写 BASE ← SIG_GATE，__DSB()，读回
三者全部一致 → 放行；否则中止并报错
```

**这不是形式主义。** 开发过程中确实出现过"`WriteOperation` 未赋值导致写通道完全失效"的缺陷，其症状（读有值、写无效）与"所有地址都别名"极其相似。门控的存在使这类故障在测量前即被拦截。

### 3.3 判定与预测的分离

扫描中每个探测点同时产生两个**互相独立**的量：

| 量 | 来源 | 性质 |
|---|---|---|
| `pred_alias` | `off % 1MB == 0` | 纯**算术**，与硬件无关 |
| `real_alias` | `alias_probe_word()` 实测 | 纯**硬件**，与算术无关 |

两者不符即打印 `!! PREDICT MISMATCH` 并计数。**这是本阶段最重要的验证手段**——两条独立路径的吻合，比"重复运行结果一致"有力得多。

## 4. 实验设计

### 4.1 实验一：1 MB 步长全窗口扫描

`base = 0x68000000`，`step = 0x00100000`，覆盖 k = 1..63（即整个 64 MB 窗口）。

### 4.2 实验二：512 KB 步长对照扫描 ★关键

`base = 0x68000000`，`step = 0x00080000`，k = 1..63。

**为什么必须有这个对照组？**

实验一的所有探测点都是 1 MB 的整数倍，因此以下**两个完全不同的假设会给出完全相同的输出**：

| 假设 | 实验一的预期输出 |
|---|---|
| H1：芯片 1 MB，别名周期 1 MB（真相） | 全部 ALIAS |
| H2：芯片只有 **1 个存储单元**，任何 ≥1 MB 的偏移都回卷到它 | 全部 ALIAS |

**实验一本质上只探测了一个等价类，无法区分"周期 = 1 MB"与"周期 = ∞"。**

实验二把探测点撒到**两个不同的等价类**上：

- 512 KB 偏移的点（非 1 MB 整数倍）→ 实测**全部 INDEP** → 否定 H2，也否定"周期 ≤ 512 KB"
- 1 MB 整数倍的点 → 实测**全部 ALIAS** → 周期 ≤ 1 MB

**两个方向一夹，周期只能是 1 MB。**

### 4.3 为什么不需要二分法

别名周期必然形如 `2^k`（别名来自高位地址线被丢弃，`单元索引 = offset mod 2^k`）。因此相邻的两个 2 的幂就足以定案：

```
0x80000  → 无别名（排除周期 ≤ 512 KB）
0x100000 → 有别名（周期 ≤ 1 MB）
────────────────────────────────────
周期 ∈ {1 MB}，唯一解
```

**实验二的副产品已经把边界夹到字节级精度，二分扫描可以省去。**

### 4.4 实验三：基准平移不变性

`base = 0x68080000`，`step = 0x00080000`，其余与实验二相同。

若判定依赖绝对地址，基准一平移，ALIAS 的分布必然改变。若分布不变，则判定只与 **`(B − A) mod 周期`** 有关——这正是"别名"的物理定义。

### 4.5 安全边界

扫描的 `B` 绝不可越过 `0x6C000000`（NE4 窗口，LCD 控制器所在），否则会把 LCD 寄存器当作 SRAM 写入，导致显示错乱。扫描函数内置范围检查，越界即拒绝执行并返回 `SCAN_ERR_RANGE`。

## 5. 测量结果

### 5.1 实验一：1 MB 步长（`base = 0x68000000`）

```
[GATE] PASS @0x68000000
[SCAN] base=0x68000000 step=0x100000 k=1..63
  k= 1 B=0x68100000  ALIAS
  ...
  k=63 B=0x6BF00000  ALIAS
[SCAN] done: alias=63 indep=0 ghost=0
```

**63 个探测点全部别名** → 周期 ≤ 1 MB。

### 5.2 实验二：512 KB 步长（`base = 0x68000000`）

```
[SCAN] base=0x68000000 step=0x80000 k=1..63
  k= 1 off=0x0080000 -     B=0x68080000  INDEP
  k= 2 off=0x0100000 @1M   B=0x68100000  ALIAS
  k= 3 off=0x0180000 -     B=0x68180000  INDEP
  k= 4 off=0x0200000 @1M   B=0x68200000  ALIAS
  ...
  k=62 off=0x1F00000 @1M   B=0x69F00000  ALIAS
  k=63 off=0x1F80000 -     B=0x69F80000  INDEP
[SCAN] done: alias=31 indep=32 ghost=0 pred_ok=63 pred_bad=0
```

观察到的规律：**ALIAS ⟺ `off` 是 1 MB 的整数倍**（31 个 ALIAS，32 个 INDEP）。

> 注：由于 `step = 512 KB`，`off` 为 1 MB 整数倍等价于 k 为偶数。此处务必注意——**规律的本质是"偏移落在 1 MB 边界上"，不是"k 是偶数"**。后者的表述会导致错误推广。

### 5.3 实验三：基准平移（`base = 0x68080000`）

```
[SCAN] base=0x68080000 step=0x80000 k=1..63
  k= 1 off=0x0080000 -     B=0x68100000  INDEP
  k= 2 off=0x0100000 @1M   B=0x68180000  ALIAS
  ...
  k=63 off=0x1F80000 -     B=0x6A000000  INDEP
[SCAN] done: alias=31 indep=32 ghost=0 pred_ok=63 pred_bad=0
```

**与实验二完全一致（31/32/0）**，ALIAS 的 k 集合未变（仍为 {2,4,...,62}）。

### 5.4 结果汇总

| 实验 | base | step | alias | indep | ghost | pred_ok | pred_bad |
|---|---|---|---|---|---|---|---|
| 一 | `0x68000000` | 0x100000 | 63 | 0 | 0 | — | — |
| 二 | `0x68000000` | 0x080000 | 31 | 32 | 0 | **63** | **0** |
| 三 | `0x68080000` | 0x080000 | 31 | 32 | 0 | **63** | **0** |

## 6. 预测闭环

本阶段的结论有两条相互独立的来源：

| 来源 | 推理链 | 结论 |
|---|---|---|
| **硬件推导** | `readme.txt` 的按键分配（PE2/PE3/PE4）→ F407 复用表中 PE2/PE3/PE4 = A23/A19/A20 → 这三根地址线被按键占用 → 可用地址线最多 A18 → 2^19 半字 = **1 MB** | 别名步长 = 1 MB |
| **实测** | 512 KB 对照实验否定"周期 ≤ 512 KB"，1 MB 实验证实"周期 ≤ 1 MB"，基准平移后结论不变 | 别名步长 = 1 MB |

**两条路径独立得出同一结论。** 这不是巧合，而是一次有效预测的证实：

```
理论预测：1 MB      ──证实──▶      实测结果：1 MB
```

一个有说服力的测量，其特征恰恰是**它验证了测量之前就成立的预测**。若实测值与预测不符，那才更需要解释。

## 7. 结论

```
==============================================
  SRAM 内存侦察兵 —— 阶段 1 结论
==============================================
  地址窗口       : 0x6800 0000 ~ 0x6BFF FFFF  (64 MB)
  基准地址       : 0x6800 0000  (NE3 / FSMC Bank1)

  最小别名步长   : 0x0010 0000  (1,048,576 字节)
  真实可用容量   : 1 MB  (0x6800 0000 ~ 0x680F FFFF)
  镜像因子       : 64    (64 MB ÷ 1 MB)
  幽灵地址数量   : 0

  镜像基址       : 0x68000000, 0x68100000, 0x68200000,
                   ... , 0x6BF00000   (共 64 个)

  判定           : 地址线 A0 ~ A18 已连接；
                   A19 及以上未连接（被按键 PE2/PE3/PE4 占用）
==============================================
```

**结论的物理含义**：访问 `0x68100000` 时，MCU 发出的 `HADDR = 0x010 0000` 中，A19 及以上位未被 SRAM 接收，芯片只看到 A18~A0 = 0，因此实际访问的是第 0 个半字。**1 MB 的物理芯片在 64 MB 的地址窗口中出现了 64 次。**

## 8. 有效性论证

本阶段结论的可信度建立在以下四条独立证据上：

### 8.1 门控自检

每次扫描前均执行写通道活体检测，三组签名全部通过（`[GATE] PASS`）。这排除了"测量工具本身失效"的可能。

### 8.2 判定基于正向证据

每个探测点的结论由 `alias_probe_word()` 通过**双向交叉写入**得出，而非推理：

- ALIAS 有证据：B 的值确实出现在了 A 的单元里
- INDEP 有证据：A 与 B **各自保持自己的值**，且 B 的写入**确已落地**
- 两向矛盾或写入未落地 → 报 GHOST，不给出不可信的结论

本次三组实验中 **GHOST 计数始终为 0**，说明所有探测点的写入均正常落地、两个方向结论一致。

### 8.3 算术预测与硬件实测的交叉验证 ★核心

`pred_alias`（算术：`off % 1MB == 0`）与 `real_alias`（硬件实测）来自**两条完全独立的代码路径**。

| 实验 | 探测点数 | 预测命中 | 预测不符 |
|---|---|---|---|
| 二 | 63 | 63 | **0** |
| 三 | 63 | 63 | **0** |
| **合计** | **126** | **126** | **0** |

**126 个数据点、零例外。** 若真实别名周期不是 1 MB，这个对应关系必然出现大量不符。因此该结果几乎不可能是巧合。

### 8.4 平移不变性

基准从 `0x68000000` 平移到 `0x68080000` 后，ALIAS 的 k 集合**完全不变**。这证明判定只依赖 `(B − A)`，即**被测的是地址之差的属性，而非任何绝对地址的属性**——这正是"别名"的定义。

### 8.5 结论

综合以上四条：**上述结论描述的是硬件本身的性质，而非算法或代码的产物。**

## 9. 本阶段发现并修复的缺陷

本阶段在开发过程中发现并修复了若干缺陷，其中数条具有典型性与隐蔽性，记录如下。

### 9.1 原始例程的缺陷

| # | 缺陷 | 症状 | 危害 |
|---|---|---|---|
| 1 | `main.c` 定义 `g_test_buffer[250000]` 占据 `0x68000000` 起的约 0.95 MB，而 KEY0 的测试函数在同一地址区间做撒点写入 | 每按一次 KEY0 即破坏该缓冲区数据 | 后续 KEY1 显示的是已被污染的数据 |
| 2 | `lcd_show_string(x, y, 239, y + 16, ...)` | 把 `y+16` 当 `height` 传入 | 显示范围计算错误 |

### 9.2 本项目实现中发现的缺陷

| # | 缺陷 | 症状 | 根因 |
|---|---|---|---|
| 3 | **`WriteOperation` 未赋值** | **写通道完全失效**：读有值、写无效 | `USE_FULL_ASSERT` 未开启，`assert_param()` 不检查任何参数；`FSMC_WRITE_OPERATION_ENABLE = 0x1000` 是唯一非零的枚举值，结构体为零初始化时 WREN=0 |
| 4 | **`FSMC_NORSRAM_TimingTypeDef` 未清零** | 时序寄存器写入**栈垃圾**，行为随机、每次编译可能不同 | 局部结构体只赋了 3 个字段，其余未初始化 |
| 5 | `sram_test_read/write` 未定义 | 链接失败 | `usmart_config.c` 已注册这两个函数 |
| 6 | **INDEP 判定无证据** | 把"写入丢失"误判为"独立单元" | 仅凭"读 A == SIG1"就下结论 |
| 7 | 单向扰动 | 无法发现单向故障造成的假 ALIAS | 只测"写 B 扰动 A" |
| 8 | LCD 行坐标重叠 | 分隔线压住相邻文字 | 分隔线用 `'-'` 字符串绘制（占满 16 px 文字行），而间隔仅 `+4` |
| 9 | Verdict 判据过弱 | 写通道部分失效时仍报"一致" | 仅检查两次扫描结果相等，未检查与算术预测的吻合 |

**缺陷 3 值得特别强调**：它的症状（所有地址看似互相别名）与"芯片只有 1 个存储单元"这一**被考察的假设之一**高度相似，极易被误读为"测量成功"。这正是必须在测量前设置门控自检的原因。

### 9.3 架构性设计约束

`HAL_SRAM_MspInit()` 在 `lcd.c` 中已定义（负责 D0~D15 与 NOE/NWE，因 SRAM 与 LCD 共用）。因此本模块**不可重复定义**该函数，否则链接报 `multiply defined symbol`。当前方案为：`lcd.c` 负责共用数据/控制线，`sram.c` 负责 NE3 与 A0~A18。**该分工并不理想，建议后续重构时统一到独立的总线初始化模块**（见第 10 节）。

## 10. 遗留问题与后续工作

### 10.1 本阶段的已知局限

以下实验因时间原因未执行，**是本阶段证据链中可被质疑的部分，需在报告中如实记录**：

| 未做的实验 | 预期结果 | 能排除的质疑 |
|---|---|---|
| **翻转测试**：`base = 0x68040000`，step = 0x80000 | 预测 **0 个 ALIAS**（63 点全 INDEP），因为 `0x40000 + k×0x80000` 永远取不到 1 MB 的整数倍 | 证明工具**能报出"没有别名"**，而非"总是报别名" |
| **签名无关性**：更换 SIG1/SIG2 | 结论不变 | 排除"总线残留碰巧撞上签名"的偶合 |
| **主动证伪**：将 PD13（A18）配为 GPIO 输出并驱动为低 | 预测别名步长**变为 512 KB** | 证明工具真的在"读引脚"，而非回显常量 |

**最需要补的是翻转测试。** 当前所有探测点的 `off` 都是 `0x80000` 的整数倍，因此"带零头的偏移是否遵循同样规律"未被验证。

| 阶段 | 内容 |

## 附录 D：术语

| 术语 | 含义 |
|---|---|
| **别名 / 镜像** | 多个不同地址映射到同一物理存储单元 |
| **别名步长** | 最小的非零别名偏移量，等于真实容量 |
| **幽灵地址** | 未连接任何存储单元的地址，读回值未定义 |
| **交叉写入** | 在两个地址分别写入不同签名，通过观察互相干扰来判定是否同单元 |
| **门控自检** | 测量前验证写通道存活的检查 |
